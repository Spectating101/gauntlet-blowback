# Project advancement briefs — internal build queue

Each brief is a bounded request suitable for a dedicated project agent. The agent must return evidence, not a maturity adjective. No brief authorizes external contact, publication, paid work or submission.

## Cite-Agent — exact served research journey

**Outcome:** one inspectable end-to-end question-to-export case.  
**Build:** use a fresh question; preserve source bytes and locators; produce a grounded answer, empirical step and manuscript/export; exercise invalidation, restart and provider trace.  
**Acceptance:** exact inputs/outputs, commands, test results, restart evidence and failure receipt are reproducible from the designated candidate.  
**Return:** case-study record, evidence paths, test transcript, limitations and canonicalization recommendation.  
**Do not claim:** external adoption, fully attested paired production release or superior research quality.

## Research Drive — persistent research-infrastructure journey

**Outcome:** one fresh non-demo ingest survives processing and restart without false completion.  
**Build:** ingest new material; preserve bytes/provenance; synthesize; restart; force one worker failure and retry; test duplicate prevention and completion truth.  
**Acceptance:** the same evidence object remains traceable across the whole journey and failure does not create duplicate or falsely complete state.  
**Return:** fixture/source, lifecycle trace, restart/failure receipts, synthesis artifact and limitations.  
**Do not claim:** broad deployment, independent lab use or production service guarantees.

## Policy Lab — new case plus negative controls

**Outcome:** prove the current system generalizes beyond its existing examples.  
**Build:** add a genuinely new case; run evidence intake, assurance, policy comparison and consequence/export; create tampered and insufficient-evidence variants.  
**Acceptance:** the valid case completes reproducibly; tampered/insufficient cases fail or remain uncertain for explicit reasons; exported outputs retain provenance.  
**Return:** fixtures, run receipt, comparison/output, negative-control evidence and claim/nonclaim update.  
**Do not claim:** policy adoption, regulator validation or real-world impact.

## Hardware Splicer — paired-evaluation apparatus

**Outcome:** complete evaluation infrastructure at the current non-physical boundary.  
**Build:** implement a matched non-destructive reference/advisory runner; audit treatment parity; test transport synthetically; bind results to the frozen package authority without rewriting it.  
**Acceptance:** matched inputs and stopping rules, parity report, deterministic synthetic tests and explicit separation from paid/scored/physical evidence.  
**Return:** runner, fixtures, parity audit, test transcript, package lineage and limitation statement.  
**Do not claim:** physical correctness, fabrication, provider approval or benchmark superiority.

## Public-Good Control Plane — complete internal operator loop

**Outcome:** one reviewable case from intake through correction.  
**Build:** fixture a case with intake, revision, bottleneck identification, proposal, explicit human decision, follow-up and correction/rejection; preserve ledger history.  
**Acceptance:** deterministic replay, visible decision authority, complete audit trail and explicit internal-only label.  
**Return:** fixture, replay command, ledger/receipt, screenshots or structured outputs and nonclaim.  
**Do not claim:** field deployment, operator effectiveness or humanitarian outcome.

## Refinery / Commons — provider execution and reuse

**Outcome:** one real authorized capability completes inside the canonical product boundary.  
**Build:** resolve a capability to an available provider; execute; evaluate; emit a reuse receipt; test provider failure and stale-mapping refusal. Use only already authorized local/provider access and avoid purchasing or external commitments.  
**Acceptance:** success path is reproducible; provider failure is visible and recoverable; stale mapping fails closed; reuse points to exact evidence.  
**Return:** capability fixture, resolution trace, evaluation, reuse receipt, failure evidence and limitations.  
**Do not claim:** general cross-project execution, universal provider compatibility or external adoption.

## Research papers — ordered authority repair

**Outcome:** create one defensible canonical writing sample before expanding venue packaging.  
**Build:** repair Fiscal Choke Points first: freeze research question, data/sample authority, identification logic, reproducibility steps, results tables and limitation ledger. Invisible Ledger remains user-owned; CEIR and ESG remain behind their empirical milestones.  
**Acceptance:** a clean reader can reproduce the selected paper's core result and identify every unresolved limitation; paper and data/code authority agree.  
**Return:** canonical manuscript, reproducibility appendix, frozen evidence manifest, open-issue ledger and release recommendation.  
**Do not claim:** acceptance, peer review, causal certainty or resolved authority for the held papers.

## Reassessment contract

For every returned brief, update the asset authority only after checking the exact artifact. Record what changed, what did not, the strongest new proof, the strongest remaining nonclaim and whether the asset now earns a person-level case-study card.
