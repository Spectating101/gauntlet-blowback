# Main Quest Preparation Leverage — 2026-09-16

The preparation rule is simple:

> **Build shared assets first when one artifact unlocks many routes. Spend route-specific effort only on irreducible deltas.**

The Main Quest denominator is 149 routes: 61 PhD + 88 employment.

## Preparation order

### 1. Canonical Facts + Evidence Spine

This is the highest-leverage object. It is not a polished CV; it is the source of truth that all CVs, resumes, SOPs, faculty emails, recommender briefs, project sheets, bios and interview stories derive from.

It should contain education/work/research history, paper maturity, project claims, skills, links, external validation, a master accomplishment bullet bank, claim-to-evidence links and short/medium/long factual bios.

**Coverage:** shared source material for 149/149 Main Quest routes.

### 2. PhD Core Dossier

Derived from the spine:

- academic CV;
- one-page research identity statement;
- research portfolio summary;
- thesis/research-object placeholder, with no asset mapping until the user establishes its authority;
- Fiscal Choke Points summary;
- systems-research summary;
- publication/output list;
- reusable SOP/research-statement modules.

The 61 PhD applications should then differ mainly in institute/faculty/research-question/form deltas rather than being rewritten from zero.

### 3. Recommender + Official Document Pack

Prepare one shared recommender/document dependency pack: academic CV, one-page research summary, target-program/deadline matrix, program-family emphasis, transcript, enrollment/expected-graduation proof, degree documents, writing samples, language evidence where needed, and a recommender request tracker.

This deserves early attention because external humans and institutional documents can become the real critical path during the Sep-Oct admissions cluster.

### 4. Five Employment Packet Families

Do not create 88 independent resumes. Create five modular families:

1. research / applied AI;
2. financial AI / FinTech;
3. quant;
4. AI software / agent systems;
5. semiconductor / EDA / physical AI.

An individual application should usually require only a few bullet swaps, a role-facing summary adjustment and portal-specific fields.

### 5. Canonical Evidence Cards

Start with four reusable one-page objects:

- Refinery;
- Hardware Splicer;
- Policy Lab;
- Cite/YZUC/Research Drive.

Each should state the problem, personal contribution, architecture/method, scale, evaluation, maturity, proven claims, nonclaims and evidence links.

### 6. 149-Route Delta Matrix

Only after shared packets exist, map every route to campaign, packet family, lead evidence, required documents, irreducible custom work, deadline, economics, eligibility gate, competition state and marginal application cost.

The two unrecovered employment identities remain `IDENTITY_GAP`; they must not be fabricated just to make the table look complete.

### 7. Interview / Oral Story Bank

Build when applications start converting. Reuse the same evidence in 30-second, 90-second and 5-minute versions for research identity, settled empirical work, Refinery, Hardware Splicer, Policy Lab, large-data work, verification/failure examples and the finance→AI-systems transition. Add a thesis/research-object story only after the user establishes its authority.

## Do not do first

- 61 bespoke SOPs;
- 88 bespoke resumes;
- route-specific packet polishing before the shared evidence spine exists;
- secondary-paper polishing merely because a venue exists;
- broad interview preparation before an interview/oral is actually approaching.

## Immediate target

The first build target is therefore **`MAIN_QUEST_CANONICAL_FACTS_EVIDENCE_SPINE`**.

Use existing repository/context evidence by default. User involvement should be reserved for factual corrections, unavailable official documents and genuinely personal decisions—not routine packaging choices.
