# Refinery / Generative Software Commons — Funding Accessibility Note

Date: 2026-08-22

This note is a strategy aid, not an eligibility determination. Current calls and programme rules must be re-verified before submission.

## Core observation

Refinery is unusually compatible with project-based funding because the newer Generative Software Commons framing maps onto established public-interest/open-source funding categories:

- open-source infrastructure;
- digital commons;
- software supply-chain security;
- provenance and attestation;
- research software;
- developer infrastructure;
- open-source sustainability;
- AI/agent governance where tied to open technical infrastructure.

The strongest funding version is not "fund my private AI startup." It is a bounded, open, falsifiable project slice with clear public outputs, milestones, licensing, and a realistic budget.

## Accessibility tiers

### Tier A — individual/project accessible

Examples include programmes that explicitly allow individuals or independent researchers, and direct maintainer sponsorship mechanisms. These are the best near-term routes because they do not require first creating a company or university grant vehicle.

Typical requirements:

- clear open-source/public-good output;
- bounded project proposal;
- public repository and licence;
- technical credibility;
- milestone/budget clarity;
- payment/tax onboarding.

### Tier B — accessible through fiscal host / umbrella

Some funding sources want a legal or financial counterparty, but the project itself need not incorporate if a suitable fiscal host accepts it. Fiscal sponsorship can supply legal status, banking, invoicing, accounting, and compliance in exchange for host fees and host policy constraints.

### Tier C — institution/entity dependent

Some grants require a legally registered company, nonprofit, association, university, or research institution. These routes are still plausible, but are not direct solo applications unless an existing institution agrees to host or submit.

### Tier D — maturity/adoption dependent

Some open-source funds support only already-critical or widely adopted projects. Refinery may become eligible later, but current internal sophistication is not equivalent to demonstrated ecosystem dependence.

## Recommended funding object

Do not submit the entire alpha-platform history as one giant initiative.

Prefer a first funded slice such as:

> **Generative Software Commons: artifact-bound capability identity and provenance for reusable open-source software components**

Possible bounded deliverables:

1. stable open object model for Capability Capsule / Implementation / Claim / Registry snapshot;
2. GitHub/forge overlay adapter for a predeclared heterogeneous corpus;
3. SPDX / SLSA-in-toto / OCI / OpenSSF evidence ingestion bound to exact implementations;
4. negative/adverse claim preservation;
5. reproducible public evaluation corpus;
6. documentation and interoperability examples;
7. independent external project integration or maintainer evaluation.

This is materially easier to fund than "Refinery, the universal platform," because reviewers can understand the public good, implementation plan, and stopping condition.

## Funding ladder

```text
GitHub Sponsors / direct support
        ↓
small project grant / fellowship
        ↓
fiscal-hosted sponsorship or grant
        ↓
serious open-infrastructure grant
        ↓
institutional / public-sector pilot
        ↓
recurring sponsors / contracts
```

The project should not need to incorporate at the first step. Legal structure should be added only when funding volume, contracting, liability or hiring makes it worthwhile.

## Evidence gates

Funding accessibility increases sharply when the project can show:

- public open-source licence;
- concise project identity;
- independent users/maintainers;
- external integrations;
- issue/PR activity from outsiders;
- adoption/dependency evidence;
- security/provenance relevance;
- a credible maintenance plan;
- budget tied to named deliverables;
- previous milestones completed on schedule.

The current portfolio is strong on technical evidence and weak on independent adoption/commitment/spend. Funding proposals must state that honestly.
