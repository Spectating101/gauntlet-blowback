## State vocabulary

- `FIRE` — application/submission is strategically justified; execute remaining reversible work.
- `FIRE_AFTER_GATE` — strong route, but one explicit eligibility/economic/legal gate must clear first.
- `FIRE_IF_FIT` — economics are attractive but portfolio thesis must be genuine rather than forced.
- `SELECTIVE_FIRE` — apply only from reusable material / strict application-hour cap.
- `VERIFY` — one or more material facts remain unresolved.
- `ROLLING` — currently live persistent rail; refresh regularly.
- `WATCH` — recurring/strategic source whose current round is closed or not yet open.
- `HOLD` — attractive but dependency/vehicle currently blocks it.
- `KILL` — known hard blocker or bad economics; preserve the reason so it is not rediscovered.

## Anti-patterns / auto-reject conditions

Reject or heavily penalize:

- competition requires core project to be newly built during the event;
- low-value prize requires days of new engineering;
- geographic/student/entity/work-authorization restriction clearly fails;
- application requires false rebranding or inflated claims;
- professor/lab page is treated as paid without salary/funding confirmation;
- full-time fellowship is treated as “free side money” rather than a career commitment;
- paid security bounty is outside demonstrated security capability;
- nominal cloud credits are counted as cash despite no planned spend;
- multiple tracks violate category/duplicate/manuscript rules;
- a closed annual fellowship is given an invented future deadline;
- a project is resurrected solely because an unrelated small prize exists.
