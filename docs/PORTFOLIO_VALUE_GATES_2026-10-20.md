## Run protocol for autonomous repository agents

1. **Start from the linked issue and its primary experiment/reference PRs.** Check current branch state and ownership. Do not edit another agent's active worktree, force-push, rebase or merge unrelated stacked drafts. Isolate changes in a new worktree/branch.
2. Before coding, write the central falsifiable question, baseline, frozen tests, data permissions, acceptance/rejection thresholds, estimated implementation effort, and exact files to modify. Retain an audit of negative results.
3. Prefer existing mature external engines and *measured* execution to new architecture; any feature added must remove an identified blocker. Do not infer scientific evidence from successful software integration.
4. Evidence classifications must remain separate: `TECHNICALLY_WORKING`, `INDEPENDENTLY_VALIDATED`, `PILOT_READY`, `EXTERNALLY_USED`, `PAID_OR_FUNDED`. Never promote automatically from one to another.
5. External test participants, confirmed contacts, portal submissions, funds, lab authorizations, physical prints, owned parts, empirical financial returns and security sign-offs **must never be fabricated**. Real-world contact, purchasing, credentials, institutional deployment and contractual commitments require the relevant user/organization authorization.
6. Every task ends in **PASS**, **FAIL**, or **BLOCKED**, with immutable source/test receipts, exact command and results, confidence limitations, link to independent assessor when applicable and next decision. A blocked result is a completed truthful diagnosis, not an invitation to generate another mock.
7. Use Gauntlet's conversion ledger only for outcome recording; it is not a scientific evaluator or product release gate. Distinguish user-reported submissions from independent confirmations, and avoid exposing applicant details in public issues.
