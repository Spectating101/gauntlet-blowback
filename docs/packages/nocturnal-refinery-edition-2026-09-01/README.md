## How to use this packet

Do **not** submit one generic story everywhere. Use one immutable evidence core and project it into one of three truthful audience views:

1. `PUBLIC_INTEREST` — information integrity, longitudinal public memory, corrections, explainable current state, public-interest monitoring.
2. `RESEARCH_SOFTWARE` — evidence identity, provenance, reproducibility, build-vs-reuse discrimination, normalized event/evidence infrastructure.
3. `RESEARCH_LAB_PHD` — demonstrated research engineering: acquisition → evidence state → persistent memory → usable interface.

The facts do not change between views. Only emphasis changes.

## Operating rule

**Package broadly; submit narrowly.**

A good interface can improve cold comprehension, demo quality and product completeness. It does **not** clear an institutional-host requirement, journalism-applicant requirement, open-source/public-release requirement, visa/degree gate, source-rights review, or venue-specific exclusion.

Final submission remains human-gated.
